# カタログ順序の観測記録

既存サイトの `/api/search?sort=rank&hits=100&offset=1` が返す上位100件の **商品IDと位置だけ**を定期保存する検証用機能です。作品タイトル・画像・動画・購入リンクは保存しません。画像や購入リンクを備えた作品紹介画面とは独立しています。

2026-11-14の実接続でHTTP 200、success=true、100件の重複しないID、連続した1〜100のcatalogRankを確認しました。既存の `api/search.js` はDMM ItemListのsort=rankを使っています。一方 `api/rankings.js` はサイト内クリック集計なので混用しません。

## できることと限界

- 前回、約24時間前、約7日前、約30日前の観測と比較。比較元の実時刻も表示します。
- 24時間等の比較は目標時刻以前の8時間以内に実測がある場合だけ表示。履歴が足りなければ未取得と表示します。
- 今回観測入り、位置の上昇・下降、今回の上位100件内にない商品を区別します。観測外の商品を101位や販売停止とは断定しません。
- APIの人気順の集計期間・更新頻度は未確認です。購入件数、リアルタイム売上、公式の日間/月間ランキング、女優ランキングは取得しません。過去の順位は遡れません。
- 時刻はUTC。日本時間は9時間加算。12時間以上古い記録には注意表示があります。

## 実行方法

Node 24で `node scripts/catalog-order-history.mjs`。初回は `.catalog-order/history.json` と `index.html` を作成します。2回目以降は6時間以上空けます。index.htmlはローカルで開け、閲覧時のAPI通信はありません。既存履歴が壊れている場合は上書きせずエラーにします。

GitHub Actionsの **Catalog order observations** はmainにマージ後、手動実行できます。初回のみ `initialize_history` にチェックして開始します。成果物 `catalog-order-history` をダウンロードしindex.htmlを開きます。前回の成果物から履歴を復元するため、成果物を削除しないでください。期限切れ・消失時は自動で空の履歴にせず停止します。手元に退避したhistory.jsonでローカル実行を再開できます。成果物が一つもない状態でinitialize_historyを再指定すると新規開始になります。

**定期実行は初期状態で無効です。** リポジトリ変数 `CATALOG_HISTORY_ENABLED=true` で有効化、削除またはfalseで停止します。GitHub Actionsの遅延・休止によって取得が抜けることがあります。有効化前に現行ホストのプラン・残枠とDMM APIの保存/利用条件を確認してください。公式API説明は今回の調査環境では地域制限のため本文を確認できていません。

## 負荷・費用を抑える制限

- 1実行で既存サイトAPIを最大1回、上位100件だけ取得。追加ページ・リトライなし、20秒で中断、応答最大4MiB。
- 保存済み履歴から最低6時間空ける制限。定期実行は1日最大4回、31日で最大124リクエスト。手動実行も同じ間隔制限です。
- 履歴35日・最大140件。成果物保持7日。失敗した取得を成功記録として残しません。
- mainへのデータコミットやサイトの再デプロイは行いません。GitHub成果物と実行ログだけを更新します。
- 公開リポジトリの標準GitHubホストrunner実行は公式説明上無料ですが、成果物保存枠は別管理です。閲覧にはGitHubログインが必要な場合があります。非公開化やプラン変更時は再確認が必要です。
- ホスト側のAPI実行/転送量は発生します。実測1回の応答サイズと残枠をもとに評価する必要があり、無料・無制限とは保証しません。初期無効のためマージだけでは定期取得は始まりません。

今回の100件応答は431,714 bytesでした。31日・124回なら約53.5MB（約51MiB）の応答本文が目安です。これはAPI実行費や他の訪問者の利用量を含む請求額ではありません。Sitesの取得可能なサイト情報には使用量・残枠・請求情報が含まれず、その確認は未完了です。
